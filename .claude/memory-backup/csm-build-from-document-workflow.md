**Trigger:** user drops a chapter document (xlsx/CSV) and says *"Build the CSM of this module"* → execute this procedure exactly. Canonical recipe: the `azurealxr-interactables` skill (Westport copy at `C:\Westport-Version-2\Claude_CSM_Setup\.claude\skills\azurealxr-interactables\`), esp. `references/token-dictionary.md §7`, `build_simplified.py`, `build-via-unrealclaude.md`. **This repo differs from Westport in one big way — see LANGUAGE PORT.** Scope: automate the *curriculum + menu*; interactions, GM `RunStepsOrder`, and maps are dev-owned. Don't commit unless asked.

**Prereqs:** editor open with the UnrealClaude plugin loaded (built for 5.8 — see [[unrealclaude-58-port]]). **Drive the editor DIRECTLY over HTTP** — do NOT rely on the `mcp__unrealclaude__*` tools registering (they usually don't, because the bridge caches an empty tool list if the editor wasn't up at Claude-Code start, and never emits `tools/list_changed`). Call: `POST http://localhost:3000/mcp/tool/<name>` with JSON body = args. `execute_script` is **async** → returns `task_id` → poll `POST /mcp/tool/task_result {task_id}`. `blueprint_modify`/`blueprint_query`/`asset`/`asset_dependencies` are sync. Build reusable Node helpers in scratchpad: `uc.js <tool> <pyFile>` (submits python via execute_script + polls task_result), `uc2.js <tool> <argsFile>` (posts JSON args, polls if async). `execute_script` needs `{script_type:"python", script_content:"# @Description: ...\n<code>"}`.

**Read the sheet:** no local `python`/`py` here → `npm i xlsx` (SheetJS) in scratchpad, `XLSX.readFile(...).Sheets[name]`, `sheet_to_json(ws,{header:1,defval:""})`. Native format columns: `No(0) / Procedure(1) / Sub-No(2) / Sub-Procedure(3) / UI(4) …`. Row 0 = chapter title; header row where `col0.toLowerCase()=="no."`; skip all-blank rows + rows where Procedure=="chapter complete"; new master step when col0 set; new sub-step when col2 set; **blank col2 continues the sub above** (so continuation rows don't add subs). **Owner rule: EVERY sub-step type = Interaction.** One sheet-tab per chapter; **skip tabs named "…On Hold".** Sheet `00` is the module index (chapter titles).

**LANGUAGE PORT — critical, differs from Westport:** `FStepData.StepTitle`, `FSubStepData.Description`, `FChapterDef.ChapterTitle` are `FAzr_MultiLangText`, NOT `FText`. In editor Python use `m=unreal.Azr_MultiLangText(); m.set_editor_property("english", text)` — NOT `unreal.Text(...)` (Westport's `populate_da.py` uses `unreal.Text` and will fail here).

**Build sequence** (each = one `execute_script` python; duplicate the plugin templates):
1. **DA per chapter** → `/Game/CSM/DA_Chapter<n>`: `EAL.duplicate_asset("/Azureal_CSM/DA_Chapter1", dst)`; class `unreal.TrainingCurriculum`, set `master_steps` = list of `unreal.StepData` (`step_type`=`unreal.MasterStepType.STANDARD`, `step_title`=mlt(title), `sub_steps`=[`unreal.SubStepData`(`description`=mlt(d), `type`=`unreal.StepType.INTERACTION`)]); `EAL.save_asset`.
2. **Module** → `/Game/CSM/Module_1`: duplicate `/Azureal_CSM/Module_1` (class `ChapterBundle`); `all_chapters` = [`unreal.ChapterDef`(`chapter_title`=mlt(title), `step_data`=EAL.load_asset(DA))]; **leave `chapter_level` + `chapter_game_manager_class` BLANK** (dev-owned); save.
3. **BP_CSM** → `/Game/CSM/BP_CSM`: `unreal.BlueprintFactory` parent `/Script/AzurealXR.Azr_Interactable`; add a `WidgetComponent` named `MenuWidget` via `SubobjectDataSubsystem` under SceneRoot; set `widget_class`=`load_class(None,"/Azureal_CSM/WBP_MainMenu.WBP_MainMenu_C")`, `relative_scale3d`=Vector(0.1,0.1,0.1), `draw_at_desired_size`=True, `set_collision_profile_name("Azr_Collision")`; compile + save. (WidgetComponents can't be added by blueprint_modify — must be python/SubobjectDataSubsystem.)
4. **BP_CSM graph** (`blueprint_modify`): Event BeginPlay already exists — get its `node_guid` from `blueprint_query get_nodes` (node_id comes back `""`, use the guid). `add_nodes` [VariableGet {variable:"MenuWidget"}, CallFunction {function:"SetVisibility", target_class:"/Script/Engine.SceneComponent"}, CallFunction {function:"EnablePointer", target_class:"/Script/AzurealXR.Azr_Interactable"}]. `set_pin_value` SetVisibility `bNewVisibility`="true". `connect_pins`: BeginPlay.`then`→SetVis.`execute`, MenuWidget.`MenuWidget`→SetVis.`self`, SetVis.`then`→EnPtr.`execute`, MenuWidget.`MenuWidget`→EnPtr.`Target`. **Connect the data `self`/`Target` before expecting a clean compile** (SetVisibility errors "Target must have a connection" until `self` is wired — resolves once it is).
5. **§7C-1 (the required menu wiring)** on the plugin `/Azureal_CSM/WBP_MainMenu` (used directly, not copied): `blueprint_query search_nodes query:"Chapter"` → results are in **`data.matches`**; find CallFunction "Initialize Chapters" (input pin `MasterList`) and "Generate Chapter List" (input pin `DataAsset`). node_id is `""` → use `node_guid`. `set_pin_value` both = `/Game/CSM/Module_1.Module_1`.

**Gotchas:** `blueprint_modify` auto-compiles but does NOT save the `.uasset` → run `asset {operation:"save_asset", asset_path}` on BP_CSM **and** WBP_MainMenu before `asset_dependencies` reflects changes. Verify §7C-1 via `asset_dependencies` (want `/Game/CSM/Module_1` present, `/Azureal_CSM/Module_1` gone) — `get_node_pins` does NOT report object-pin defaults. `execute_script` prints a harmless `[WARNING: no new actors created]` for asset scripts. Editing the plugin's WBP_MainMenu is an accepted plugin→project reference (project-local plugin), but a plugin re-import resets those 2 pins.

Validated end-to-end 2026-07-27 on the 11kV Switching sheet → `/Game/CSM/{DA_Chapter1,DA_Chapter2,Module_1,BP_CSM}`.
