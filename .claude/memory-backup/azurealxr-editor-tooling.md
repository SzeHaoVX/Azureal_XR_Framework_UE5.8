`Plugins/AzurealXR/Source/AzurealXREditor/` is a second module on the AzurealXR plugin (`Type: Editor`, `PostEngineInit`, Win64-only — never enters Android/game targets). It stamps an Azureal interaction "flow" onto an Actor Blueprint: adds the interaction **component**, then on the Event Graph builds `Enable X`→`EnableX`/`Disable X`→`DisableX` custom-event→call pairs (event & call share a Y so the exec wire is horizontal; Target fed by a component `VariableGet` dropped below), plus the `On*` **component-bound events**, wraps the set in a titled `UEdGraphNode_Comment` box (`GRAB NORMAL`, `LATCH`, …), then compiles. One FScopedTransaction (undoable). **NOT idempotent — each add auto-numbers a new instance** (per the user's "add multiple" request): first `Azr_Grab`, then `Azr_Grab_2`, `Azr_Grab_3`… with the whole set suffixed (`Enable Grab_2`, VariableGet/bound events → `Azr_Grab_2`, comment `GRAB NORMAL 2`) and each set laid out below the previous. Unique suffix computed by scanning the skeleton class for existing `Base`/`Base_N` properties. Layout/number constants live at the top of `AzrFlowBuilder.cpp`. **Two gotchas learned the hard way:** (1) the FText `USubobjectDataSubsystem::RenameSubobject` did NOT actually apply the numbered name to 2nd+ instances (property lookup then failed → "property missing" + no nodes) — use the FName `USubobjectDataSubsystem::RenameSubobjectMemberVariable(BP, Handle, Name)` and then read the authoritative name back via `Handle.GetData()->GetVariableName()` before the lookup. (2) `UEdGraphNode_Comment::PostPlacedNewNode()` hard-resets `NodeComment` to `"Comment"`, and `FGraphNodeCreator::Finalize()` calls it — so set `Comment->NodeComment` AFTER `Finalize()`, never before. Comment title = `Def.Group` uppercased (+ instance number).

**Data-driven — adding a new flow is ONE table row, no UI/builder code.** The registry `FAzrInteractionFlows::All()` (`AzrInteractionFlows.cpp`) is a `TArray<FAzrFlowDef>` where each row = `{Id, Group, Label, ClassPath, ComponentVarName, EnableFunction, DisableFunction, EnableEventLabel, DisableEventLabel, EventDelegates[], Tooltip}`. Empty EnableFunction/DisableFunction/EventDelegates ⇒ that piece is skipped (e.g. **Attach Target** = component only; `UAzr_AttachTarget` has no Enable/Disable/delegates). Current rows: **Grab** Normal/Attach/Remove/Trigger (all one `Azr_Grab` component; `EnableGrab`/`DisableGrab`, `EnableGrabAttach`/`DisableGrabAttach`, `EnableGrabRemove`/`DisableGrabRemove`, `EnableGrabTrigger`/`DisableGrabTrigger`; events OnGrabbed/OnReleased, OnGrabAttached/OnGrabDetached, OnGrabRemoved, OnGrabTriggered/OnGrabTriggerReleased), **Latch** (`EnableLatch`/`DisableLatch`; OnValueChanged/OnLatched/OnLatchReleased — mode Angular/Linear/Rotation is a component property, so ONE flow not three), **Touch** (`EnableTouch`/`DisableTouch`; OnTouched/OnUntouched), **Attach Target** (`Azr_AttachTarget`, component only — no enable/disable/events), **Explain** (`Azr_Explain` `EnableExplain`/`DisableExplain`; OnExplainStarted/OnExplainCompleted), **Explain+** (same `Azr_Explain` component, `EnableExplainPlus`/`DisableExplain`; OnExplainPlusStarted/OnExplainPlusCompleted), **Action** (`Azr_Action` `EnableAction`/`DisableAction`; OnActionCompleted/OnStartButtonPressed/OnCompletedButtonPressed), **Label** (`Azr_Label` `EnableLabel`/`DisableLabel`; no events). Guidance-UI component headers: `Azr_Explain.h`/`Azr_Action.h`/`Azr_Label.h`.

**One generic builder + three entry points, all → `FAzrFlowBuilder::BuildFlow(UBlueprint*, const FAzrFlowDef&)`:**
- **F1 hotkey** (`AzrGrabHotkeyProcessor`): Slate `IInputProcessor` at `EInputPreProcessorType::Editor`; consumes F1 **only** when focus is in a BP graph (walk `GetKeyboardFocusedWidget()` up to `SGraphEditor`→`GetCurrentGraph()`, else return false so F1 stays Help). Builds `FindById("GrabNormal")`.
- **Single `Azureal ▾` toolbar combo button** + **Content Browser `Add Azureal Interaction ▸` submenu** (`AzrFlowMenus`, chosen over N flat buttons to avoid crowding as flows grow): `UToolMenus::RegisterStartupCallback` → `ExtendMenu("AssetEditor.BlueprintEditor.ToolBar")` (combo via `FToolMenuEntry::InitComboButton` + `FNewToolMenuChoice`/`FNewToolMenuDelegate`) and `ExtendMenu("ContentBrowser.AssetContextMenu")` (`AddDynamicEntry`→`AddSubMenu`), owner-scoped (`FToolMenuOwnerScoped`+`UnregisterOwner`). Menu generated from the registry grouped by `Group` (multi-flow group ⇒ submenu, single ⇒ direct entry). Resolve the clicked BP via `Context.FindContext<UBlueprintEditorToolMenuContext>()->GetBlueprintObj()` (fallback `UAssetEditorToolkitMenuContext`→toolkit, guard `GetToolkitFName()=="BlueprintEditor"`→`StaticCastSharedPtr<FBlueprintEditor>`); CB filters `GetSelectedAssetsOfType(UBlueprint::StaticClass(), EIncludeSubclasses::No)`.

**Verified UE5.8 node/graph recipe (reuse for any similar editor tool):** node creation = `FGraphNodeCreator<T>` (set NodePos* then `Finalize()` — it AllocateDefaultPins+adds; never call those yourself). `UK2Node_CustomEvent::CustomFunctionName`; `UK2Node_VariableGet::VariableReference.SetSelfMember(FName)`; `UK2Node_CallFunction::SetFromFunction(UFunction*)` (self pin = `UEdGraphSchema_K2::PN_Self`); `UK2Node_ComponentBoundEvent::InitializeComponentBoundEventParams(FObjectProperty*, FMulticastDelegateProperty*)` (comp prop from the BP skeleton class, delegate prop from the component's class). Connect via `Graph->GetSchema()->TryCreateConnection`. **Add a component** = `USubobjectDataSubsystem::Get()` → `K2_GatherSubobjectDataForBlueprint` → `AddNewSubobject(FAddNewSubobjectParams{ParentHandle=Handles[0], NewClass, BlueprintContext}, FailReason)` → `RenameSubobject`, then **compile before** creating VariableGet/ComponentBoundEvent that reference it (the skeleton `FObjectProperty` only appears post-compile). Compile via `FKismetEditorUtilities::CompileBlueprint` after `FBlueprintEditorUtils::MarkBlueprintAsStructurallyModified`. Component classes resolved by path (`/Script/AzurealXR.Azr_*`, no header include → dodges CableComponent transitive deps). Build.cs deps: `UnrealEd, Kismet, KismetCompiler, BlueprintGraph, SubobjectDataInterface, ToolMenus, ContentBrowser, Slate, SlateCore, InputCore`.

**Tether Tag widget (added per user request):** flows whose registry row sets `TagWidgetName` (Grab modes → "GrabTag", Latch → "LatchTag", Touch → "TouchTag", Attach Target → "AttachTargetTag"; guidance UI = none) ALSO add a `UWidgetComponent` (module **UMG**) configured to WidgetClass `/AzurealXR/Interaction/Explain_Action_Tag_Label/Tag.Tag_C` (via `LoadClass<UUserWidget>`), scale 0.05, `SetDrawAtDesiredSize(true)`, then point the interaction component's `FAzr_TetherConfig.TargetWidgetName` at the widget's name and set `bEnableTether=true`. The tether config path differs per component (`TetherStructPath` field): Grab is per-mode (`Grab.TetherSettings` / `GrabAttach.TetherSettings` / `GrabRemove.TetherSettings` / `GrabTrigger.TetherSettings`), Latch/Touch/AttachTarget have one direct `TetherSettings` — set REFLECTIVELY (walk FStructProperty path, then `FNameProperty::SetPropertyValue_InContainer`) so no Azr headers are #included. Mutate a component TEMPLATE via `const_cast<T*>(Handle.GetData()->GetObjectForBlueprint<T>(BP))` + `SetFlags(RF_Transactional)`+`Modify()` (the private `GetMutableObjectForBlueprint` is friend-only; const_cast of `GetObjectForBlueprint` is the engine's own pattern). Widget auto-numbers GrabTag/GrabTag1/…; the interaction uses the engine auto-name (Azr_Grab/Azr_Grab1) — no interaction rename. **Rename gotcha refined: `RenameSubobjectMemberVariable` only takes effect AFTER the member exists on the skeleton, i.e. after a compile — so add components → compile → THEN rename the widget.** **Component visualizer:** `FAzrHandScannerVisualizer` (registered via `GUnrealEd->RegisterComponentVisualizer(UAzr_HandScanner::StaticClass()->GetFName(), …)` in StartupModule, unregistered in Shutdown) draws the scanner's runtime-only capsules in the BP/level viewport when the scanner is selected — red interact capsule, yellow distance capsule + aim line (mirrors `UpdateDistanceCapsuleShape`), cyan axes marking the grab snap frame. Needed because the capsules only exist at runtime so there is otherwise nothing to see while authoring. APIs: `FComponentVisualizer::DrawVisualization(Component, View, PDI)` (`ComponentVisualizer.h`, UnrealEd), `DrawWireCapsule(PDI, Base, X, Y, Z, FLinearColor, Radius, HalfHeight, Sides, SDPG_Foreground)` (`PrimitiveDrawingUtils.h`). This is why the editor module has an `AzurealXR` Build.cs dependency. See [[grab-hand-scanner-rotation]]. Because it's a native module, code/menu changes need a full **Build.bat Azureal_XR_V2Editor** with the **editor closed** (Live Coding can't re-run StartupModule / re-register menus); reopen to load. Add a new interaction type = one `FAzrFlowDef` row (verify the exact `Enable*/Disable*` UFUNCTION + `BlueprintAssignable` delegate names in the component header first).
